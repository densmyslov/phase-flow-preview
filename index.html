Purpose

ArchDesign is the interior-design application in this platform: start from a floor plan, get an empty 3D room, place furniture, control what shows through the windows, choose a design direction, and generate design images.

This document is the phase map for that workflow:

  • Phase 0 — accept the floor plan (optionally mark rooms on the 2D room canvas), link room photos, and build or author an empty 3D shell (metric footprint or native asset)
  • Phase 1 — import and qualify a native empty shell in the app (Path B upload / accept)
  • Phase 2 — place furniture in the qualified shell (clay / owner review; 2B registers native artifacts in Scenes)
  • Phase 3 — exterior through the windows (3A evidence, 3B masks / apply, 3C camera diagnostic)
  • Before Phase 4 — Q1 room references for the furnished room; a saved Q1 direction opens the design interview
  • Phases 4–6 — finished reference from the finalized interview, control package, then Sunburst design images

Feature contracts stay in their runbooks. This file only orders the stages.

Phase 0 — upstream of Phase 1

Goal: leave one workspace room with an accepted spatial plan, current linked photo evidence, and an empty 3D shell produced by at least one of the two build paths below—ready for Phase 1 when the chosen path is native import qualification.

Phase 0 does not run the Phase 1 application accept (“source import and furniture removal only”). It does not place furniture or bind exterior projection.

Shared upstream steps

  1. Floor-plan source in the workspace
    Authorized original floor-plan media is available to ArchDesign (size/dimension limits per the floor-plan analysis contract).
  2. Start floor-plan analysis
    Run the interior-design.floor-plan-adjacency workflow (current version, providers and limits in floor-plan-editing.md). This produces the editable graph candidate.
  3. Review and edit the floor-plan graph
    In the Floor plan modal, review rooms, printed dimensions, and connections against the original drawing.
  4. Save draft and accept the floor plan
    Human-accept the exact draft (draft/accept). Acceptance creates an immutable plan revision. Rooms are not accepted individually.
  5. Link current photos to the target room
    Attach at least one current JPEG, PNG, or WebP to the selected room (evidence identity for later shell work).

2D room canvas (beside the graph)

In production, open Media → Floor plan → 2D room canvas (isolated development: Media → Floorplans → Open Room canvas). The canvas works on the same floor-plan source, before or after graph acceptance:

  • Identify room sections proposes room outlines after an explicit, cost-bounded consent. Outlines are proposals: draw missing rooms, correct labels and outlines, then Save room draft.
  • Update dimensions saves corrected length, width, ceiling height and units beside the printed values. Dimensions never resize an outline or build a shell.
  • Link interior images attaches private Media images to one canvas room. Link 2D exterior images attaches images to one reviewed exterior boundary. These are 2D references: they do not identify a 3D shell wall, a window or the view through it (that is Phase 3).
  • Accept reviewed canvas is a separate human review. Graph acceptance stays independent; linking canvas rooms to graph spaces needs explicit choices against a current accepted graph revision.

The canvas belongs to Phase 0 but is not an exit gate: the graph, content links and the downstream stage gates keep their own authority. Contract: room-canvas.md.

Empty-shell construction (both paths)

Phase 0 includes both ways to obtain an empty 3D room. A given room may use one path or both over time; they are different products, not sequential stages.

Path A — Metric footprint build

ArchDesign builds a simple measured room from reviewed geometry: footprint polygon, height, wall thickness, openings, fit/check measurements. Modal/Blender extrudes that geometry into an editable metric shell (.blend, GLB, preview, QA). Linked photos stay as evidence digests; they are not sent for vision reconstruction.

  • UI: “Review metric geometry” / “Build room shell” in RoomShellPanel
  • API: shell-draft, metric shell-builds
  • Worker: services/modal-room-shell/blender_build.py

Path B — Native asset creation

An exact empty room is authored as a rich native .blend or .glb (architecture, fixed fixtures, materials, lighting, saved cameras). Creation of that file is part of Phase 0. It may happen in Blender or another DCC outside the ArchDesign import form; the Phase 0 deliverable is the empty native asset ready for Phase 1 upload.

Phase 0 native creation does not include the ArchDesign upload, Modal import job, or “Accept source import and furniture removal only”—those are Phase 1.

Exit

Phase 0 is complete for a room when:

  • the spatial plan has an immutable accepted revision that is still the current head;
  • the target room exists on that accepted graph;
  • the room has at least one current linked photo of an allowed type;
  • and at least one empty-shell path has produced its deliverable:
    • Path A: a succeeded (and, when required by downstream use, accepted) metric footprint shell for that room; and/or
    • Path B: an exact empty native .blend or .glb ready to upload for Phase 1.

Explicitly out of scope for Phase 0

  • Phase 1 native upload / Modal import / “Accept source import and furniture removal only”
  • Furniture schedule / clay placement (Phase 2)
  • Exterior evidence, masks, and camera diagnostics (Phase 3)
  • The still-deferred general “reconstruct from plan photos by vision” product vision beyond today’s metric footprint path

Before Phase 4 — Q1 room references and design interview

Q1 asks “Which spaces appeal to you?” once for each accepted room. It is not a numbered phase: it sets the design direction that Phase 4 implements.

  1. Choose Q1 room references
    Q1 ranks Magnificent-16 reference room images by similarity to this room. Its source is the room’s current accepted shell and a reviewed, processed furniture layout for the same room (Phase 2); without both, Q1 does not start. An applied Phase 3B exterior calibration on that shell joins the search when present. The owner picks reference images, or answers “None of these feel right yet”, and saves. Camera choices do not change Q1; a changed shell, layout, exterior calibration or reference corpus starts a new room search.
  2. Save the Q1 direction
    Saving the picks generates a Q1 design direction. The owner can read and edit it beside the interview.
  3. Run the design interview
    With Q1 synthesis enabled, a room-design interview starts only when the room’s Q1 is saved with at least one reference image. Reopening Q1 blocks new interviews until it is saved again, and a changed Q1 marks interviews already started as stale.

Phase 4 accepts only a finalized interview bound to a saved Q1 direction. Contract: room-q1-references.md; interview: room-image-prompt-interviewer.md.

Glossary

Definitions for the dotted terms above, as written in the room-shell and spatial-plan glossary.

Accepted spatial plan

A spatial plan that has an immutable accepted revision. An editor saved a draft graph and explicitly accepted it (draft/accept). Shell and downstream work require that accepted revision, not an unsaved candidate or draft-only edit.

Spatial plan

The processed floor-plan record for a workspace (plan_id). It holds the semantic graph of spaces, connections, dimensions, and related analysis history. Routes live under /api/v1/workspaces/{workspaceId}/interior-design/spatial-plans/{planId}.

Room (space)

One space in the spatial-plan graph, identified by space_id (for example a living room or kitchen). In the Floor plan UI, this is the room selected in the room-shell panel.

Linked photo / content link

A workspace media item attached to a plan target such as a room (space), with its own content-link revision. For metric shell drafts, linked photos are required as evidence identity (digest snapshot). Historical footprint and native-shell construction jobs do not send those photo bytes to Modal.

Room shell

An editable 3D representation of one room’s architecture (walls, floor, ceiling, openings), stored with artifacts (.blend, GLB, preview, manifest, QA) and optionally saved camera views. Owned by the ArchDesign spatial API for drafts, builds, acceptance, the current room pointer, and cameras.

Metric footprint build (Phase 0 Path A)

Same idea as the metric / historical footprint shell build: ArchDesign builds a simple measured empty room from reviewed footprint geometry. This is a Phase 0 construction path.

Native asset creation (Phase 0 Path B)

Authoring the exact empty native .blend or .glb (outside or beside the ArchDesign import form). The file is a Phase 0 deliverable; uploading and accepting it in ArchDesign is Phase 1.

Native empty-shell (native import)

Phase 1 path that imports an exact native room source produced in Phase 0 Path B (.blend or .glb), preserves architecture, fixed fixtures, materials, lighting, and selected saved cameras, and removes listed loose furniture. This is Phase 1 in the interior workflow and dimensioned-furniture docs. It does not reconstruct the room from the floor-plan drawing and photos.

Source import and furniture removal only

The explicit meaning of native-shell acceptance. It advances the canonical room-shell head after checking accepted plan/source and parent binding. It does not claim measured accuracy, exterior fidelity, final framing, design acceptance, or paid eligibility.

Phase 0 (upstream of Phase 1)

Everything required before Phase 1 native empty-shell import qualification: floor-plan source, analysis, graph review/accept, room photo links, and empty-shell construction by both named paths—metric footprint build (ArchDesign extrudes reviewed geometry) and native asset creation (author the empty .blend/.glb). Phase 0 does not run the Phase 1 upload/accept. See interior-workflow-phases.md.

Phase 1 (native import qualification)

Native empty-shell import / qualification through the application (upload Path B asset, Modal import, accept source import and furniture removal only). Requires Phase 0 shared steps plus the native file from Path B. Metric footprint builds are Phase 0 Path A, not Phase 1.

Phase 2

Furniture plan placement in the qualified room shell: schedule, clay/diagnostic views, owner placement review. Does not by itself approve final production camera or paid imagery.

Phase 3A exterior evidence

Transport and verify one exact exterior source against the current accepted shell and binding. Produces review overlays and remains blocked-awaiting-calibration-review. No accept/apply route; no Blender projection; no paid/final eligibility.

Phase 3B exterior calibration / reviewed masks

Human-reviewed masks and opening mapping for every current shell opening. Creation, acceptance, and apply are separate gates. Apply compare-and-swaps the accepted review into current exterior projection authority only—not camera, final render, or paid approval.

Phase 3C

Later exterior/camera diagnostic stage that uses applied calibration authority with a level straight-on control camera. Still not final appearance / Sunburst clearance by itself.

Artifacts

Versioned outputs stored in ArchDesign-owned AWS storage. Browsers receive short-lived download URLs. Native builds also emit one architectural PNG per reviewed source camera (two to five cameras).

Exterior-view

Content-link role for a photo used as exterior outlook / glazing context. Phase 3A transports one exact version-pinned exterior-view source; it does not change shell geometry.

Sunburst

Bounded paid image-generation campaign used only after later control-package approval. Empty-shell and early Phase 3 artifacts are not Sunburst inputs.
