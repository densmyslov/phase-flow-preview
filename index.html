Purpose

ArchDesign is the interior-design application in this platform: start from a floor plan, get an empty 3D room, place furniture, control what shows through the windows, and generate design images.

This document is the phase map for that workflow:

  • Phase 0 — accept the floor plan, link room photos, and build or author an empty 3D shell (metric footprint or native asset)
  • Phase 1 — import and qualify a native empty shell in the app (Path B upload / accept)
  • Phase 2 — place furniture in the qualified shell (clay / owner review; 2B registers native artifacts in Scenes)
  • Phase 3 — exterior through the windows (3A evidence, 3B masks / apply, 3C camera diagnostic)
  • Phases 4–6 — finished reference, control package, then Sunburst design images

Feature contracts stay in their runbooks. This file only orders the stages.

Phase 0 — upstream of Phase 1

Goal: leave one workspace room with an accepted spatial plan, current linked photo evidence, and an empty 3D shell produced by at least one of the two build paths below—ready for Phase 1 when the chosen path is native import qualification.

Phase 0 does not run the Phase 1 application accept (“source import and furniture removal only”). It does not place furniture or bind exterior projection.

Shared upstream steps

1. Floor-plan source in the workspace Authorized original floor-plan media is available to ArchDesign (size/dimension limits per the floor-plan analysis contract).

2. Start floor-plan analysis Run interior-design.floor-plan-adjacency@5.0.0 (GLM observations + Groq graph). This produces the editable semantic graph candidate.

3. Review and edit the floor-plan graph In the Floor plan modal, review rooms, printed dimensions, and connections against the original drawing.

4. Save draft and accept the floor plan Human-accept the exact draft (draft/accept). Acceptance creates an immutable plan revision. Rooms are not accepted individually.

5. Link current photos to the target room Attach at least one current JPEG, PNG, or WebP to the selected room (evidence identity for later shell work).

Empty-shell construction (both paths)

Phase 0 includes both ways to obtain an empty 3D room. A given room may use one path or both over time; they are different products, not sequential stages.

Path A — Metric footprint build

ArchDesign builds a simple measured room from reviewed geometry: footprint polygon, height, wall thickness, openings, fit/check measurements. Modal/Blender extrudes that geometry into an editable metric shell (.blend, GLB, preview, QA). Linked photos stay as evidence digests; they are not sent for vision reconstruction.

  • UI: “Review metric geometry” / “Build room shell” in RoomShellPanel
  • API: shell-draft, metric shell-builds
  • Worker: services/modal-room-shell/blender_build.py

Path B — Native asset creation

An exact empty room is authored as a rich native .blend or .glb (architecture, fixed fixtures, materials, lighting, saved cameras). Creation of that file is part of Phase 0. It may happen in Blender or another DCC outside the ArchDesign import form; the Phase 0 deliverable is the empty native asset ready for Phase 1 upload.

Phase 0 native creation does not include the ArchDesign upload, Modal import job, or “Accept source import and furniture removal only”—those are Phase 1.

Exit

Phase 0 is complete for a room when:

  • the spatial plan has an immutable accepted revision that is still the current head;
  • the target room exists on that accepted graph;
  • the room has at least one current linked photo of an allowed type;
  • and at least one empty-shell path has produced its deliverable:

- Path A: a succeeded (and, when required by downstream use, accepted) metric footprint shell for that room; and/or - Path B: an exact empty native .blend or .glb ready to upload for Phase 1.

Explicitly out of scope for Phase 0

  • Phase 1 native upload / Modal import / “Accept source import and furniture removal only”
  • Furniture schedule / clay placement (Phase 2)
  • Exterior evidence, masks, and camera diagnostics (Phase 3)
  • The still-deferred general “reconstruct from plan photos by vision” product vision beyond today’s metric footprint path

Phase 1 — native empty-shell import qualification

Upload the Phase 0 native asset (Path B), run the native empty-shell job, and accept source import and furniture removal only. See room-shells.md and dimensioned-furniture-scenes.md. Requires Phase 0 shared steps plus Path B’s native file. Metric Path A shells may already be accepted in Phase 0; they are not what Phase 1’s native-import accept means.
